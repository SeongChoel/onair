# onair 첫 버전 (MVP)

Status: ready-for-agent

## Problem Statement

치지직 같은 라이브 스트리밍 서비스를 직접 만들어 보고 싶지만, 시작점이 없다. 실제 서비스처럼 스트리머가 OBS로 방송하고 시청자가 보면서 채팅하는 핵심 흐름을 갖추되, 로그인 같은 부수 기능에 발이 묶이지 않고 내 PC 하나에서 모든 기능을 쉽게 켜고 확인할 수 있어야 한다. 이후 기능을 하나씩 붙여 갈 수 있도록 작고 단단한 첫 버전이 필요하다.

## Solution

onair라는 웹 서비스를 만든다. 스트리머는 스튜디오에서 채널을 만들고, 송출 키를 OBS에 넣고, 제목을 정해 방송 시작을 누른 뒤 OBS로 송출한다. 시청자는 채널 목록에서 라이브 중인 채널을 골라 영상을 보고, 닉네임을 정해 그 방송의 채팅에 참여한다. 영상 수신과 변환은 MediaMTX가 맡고(ADR-0001), onair는 채널·방송·채팅·스튜디오를 맡는다. 로그인은 없다. 명령 하나로 onair와 MediaMTX가 함께 켜지고, OBS 없이도 테스트 방송을 송출하는 스크립트가 있다.

## User Stories

### 채널 목록

1. 시청자로서, 첫 화면에서 채널 목록을 보고 싶다. 그래야 볼 방송을 고를 수 있다.
2. 시청자로서, 라이브 중인 채널이 목록 맨 앞에 나오길 원한다. 그래야 지금 볼 수 있는 방송을 바로 찾는다.
3. 시청자로서, 라이브 중인 채널에 LIVE 표시와 방송 제목이 보이길 원한다. 그래야 무슨 방송인지 들어가기 전에 안다.
4. 시청자로서, 라이브 중이 아닌 채널도 목록에서 보고 싶다. 그래야 어떤 채널이 있는지 안다.
5. 시청자로서, 각 채널의 프로필 이미지와 이름을 보고 싶다. 그래야 채널을 쉽게 구분한다.
6. 시청자로서, 프로필 이미지가 없는 채널은 채널 이름 첫 글자로 된 기본 이미지로 보이길 원한다. 그래야 목록이 깨져 보이지 않는다.
7. 시청자로서, 채널을 누르면 그 채널 페이지로 가고 싶다. 그래야 방송을 볼 수 있다.

### 시청

8. 시청자로서, 라이브 중인 채널 페이지에서 영상을 재생하고 싶다. 그래야 방송을 본다.
9. 시청자로서, 채널 페이지에서 채널 이름, 프로필 이미지, 방송 제목을 보고 싶다. 그래야 무엇을 보고 있는지 안다.
10. 시청자로서, 방송은 진행 중인데 영상 신호가 없으면 "영상 신호 없음"이 보이길 원한다. 그래야 화면이 멈춘 이유를 안다.
11. 시청자로서, 영상 신호가 다시 들어오면 새로고침 없이 이어서 볼 수 있길 원한다. 그래야 잠깐 끊겨도 계속 본다.
12. 시청자로서, 라이브 중이 아닌 채널 페이지에서는 "방송 중이 아닙니다"가 보이길 원한다. 그래야 기다릴지 다른 채널로 갈지 정한다.
13. 시청자로서, 보고 있던 방송이 종료되면 화면이 "방송 중이 아닙니다"로 바뀌길 원한다. 그래야 방송이 끝났다는 걸 안다.

### 채팅

14. 시청자로서, 라이브 중인 채널 페이지에서 그 방송의 채팅을 보고 싶다. 그래야 다른 시청자와 함께 즐긴다.
15. 시청자로서, 채팅에 들어가면 최근 채팅 메시지 50개를 먼저 보고 싶다. 그래야 대화 흐름을 따라간다.
16. 시청자로서, 다른 시청자가 보낸 채팅 메시지가 새로고침 없이 바로 보이길 원한다. 그래야 실시간으로 대화한다.
17. 시청자로서, 처음 채팅하려 할 때 닉네임을 정하고 싶다. 그래야 내 채팅 메시지에 이름이 붙는다.
18. 시청자로서, 정한 닉네임이 브라우저에 기억되길 원한다. 그래야 다음에 다시 입력하지 않는다.
19. 시청자로서, 닉네임을 바꾸고 싶다. 그래야 다른 이름으로 채팅할 수 있다.
20. 시청자로서, 다른 사람과 같은 닉네임도 쓸 수 있길 원한다. 그래야 이름 때문에 막히지 않는다.
21. 시청자로서, 채팅 메시지를 보내면 내 닉네임과 함께 모두에게 보이길 원한다. 그래야 누가 말했는지 안다.
22. 시청자로서, 빈 메시지나 너무 긴 메시지는 보내지지 않길 원한다. 그래야 채팅이 어지럽지 않다.
23. 시청자로서, 방송이 새로 시작되면 채팅이 비어 있는 상태로 시작하길 원한다. 그래야 지난 방송 대화와 섞이지 않는다.
24. 시청자로서, 라이브 중이 아닌 채널에서는 채팅 입력이 막혀 있길 원한다. 그래야 보낼 수 없는 메시지를 쓰지 않는다.
25. 시청자로서, 내가 보낸 뒤 닉네임을 바꿔도 이미 보낸 채팅 메시지의 닉네임은 그대로이길 원한다. 그래야 대화 기록이 바뀌지 않는다.

### 스튜디오: 채널 만들기

26. 스트리머로서, 스튜디오에서 채널 이름을 입력해 채널을 만들고 싶다. 그래야 방송할 곳이 생긴다.
27. 스트리머로서, 이미 있는 이름으로는 채널을 만들 수 없다는 안내를 받고 싶다. 그래야 다른 이름을 고른다.
28. 스트리머로서, 채널을 만들면 송출 키를 바로 받고 싶다. 그래야 OBS에 넣을 수 있다.
29. 스트리머로서, 채널을 만든 브라우저가 송출 키를 기억하길 원한다. 그래야 스튜디오에 다시 들어갈 때 입력하지 않는다.
30. 스트리머로서, 스튜디오에서 송출 키를 언제든 다시 보고 복사하고 싶다. 그래야 OBS 설정을 다시 할 수 있다.
31. 스트리머로서, 스튜디오에서 OBS에 넣을 서버 주소도 함께 보고 싶다. 그래야 OBS 설정을 한 화면에서 끝낸다.

### 스튜디오: 들어가기

32. 스트리머로서, 송출 키를 입력해 내 채널의 스튜디오에 들어가고 싶다. 그래야 다른 브라우저에서도 방송을 관리한다.
33. 스트리머로서, 틀린 송출 키로는 스튜디오에 들어갈 수 없길 원한다. 그래야 남이 내 방송을 켜거나 끄지 못한다.
34. 스트리머로서, 스튜디오에서 나가면 브라우저에 저장된 송출 키가 지워지길 원한다. 그래야 공용 PC에 남지 않는다.

### 스튜디오: 방송

35. 스트리머로서, 방송 제목을 입력하고 방송 시작을 누르고 싶다. 그래야 새 방송이 시작된다.
36. 스트리머로서, 제목을 비워 두면 "{채널 이름}의 방송"이 제목이 되길 원한다. 그래야 제목 없이도 바로 시작한다.
37. 스트리머로서, 방송 시작을 누른 뒤 OBS로 송출하면 영상이 시청자에게 나가길 원한다. 그래야 방송을 한다.
38. 스트리머로서, 방송 시작 전에 OBS로 송출하면 거부되길 원한다. 그래야 방송은 항상 버튼으로만 시작된다.
39. 스트리머로서, 스튜디오에서 지금 영상 신호가 들어오는지 보고 싶다. 그래야 OBS가 제대로 송출 중인지 안다.
40. 스트리머로서, 이미 방송 중일 때는 방송 시작을 또 누를 수 없길 원한다. 그래야 방송이 두 개 생기지 않는다.
41. 스트리머로서, 방송 종료를 눌러 방송을 끝내고 싶다. 그래야 시청자에게 방송이 끝났음을 알린다.
42. 스트리머로서, 방송 종료 후 OBS가 계속 송출해도 영상이 시청자에게 나가지 않길 원한다. 그래야 끝난 방송이 새어 나가지 않는다.
43. 스트리머로서, OBS 송출이 끊겨도 방송이 자동으로 끝나지 않길 원한다. 그래야 잠깐 끊겼다가 다시 이어서 방송한다.
44. 스트리머로서, 방송을 끄고 다시 켜면 새 방송으로 시작하길 원한다. 그래야 방송마다 제목과 채팅이 따로 있다.

### 스튜디오: 프로필 이미지

45. 스트리머로서, 채널 프로필 이미지를 올리고 싶다. 그래야 내 채널이 눈에 띈다.
46. 스트리머로서, jpg, png, webp가 아니거나 2MB가 넘는 파일은 거부되고 이유를 보고 싶다. 그래야 맞는 파일로 다시 올린다.
47. 스트리머로서, 프로필 이미지를 새로 올리면 기존 이미지가 바뀌길 원한다. 그래야 이미지를 교체한다.

### 로컬 개발과 테스트

48. 개발자로서, 명령 하나로 onair와 MediaMTX를 함께 켜고 싶다. 그래야 매번 여러 프로그램을 따로 켜지 않는다.
49. 개발자로서, 처음 켤 때 테스트 채널 3개가 자동으로 들어가길 원한다. 그래야 바로 화면을 확인한다.
50. 개발자로서, 테스트 채널의 송출 키를 알고 싶다. 그래야 스튜디오와 테스트 방송에 바로 쓴다.
51. 개발자로서, OBS 없이 명령 하나로 특정 채널에 테스트 영상과 소리를 송출하고 싶다. 그래야 방송 흐름 전체를 혼자 확인한다.
52. 개발자로서, 테스트 송출에 영상 파일이 필요 없길 원한다. 그래야 따로 내려받을 것이 없다.
53. 개발자로서, 데이터 파일을 지우면 깨끗한 상태로 다시 시작하길 원한다. 그래야 꼬인 상태를 쉽게 초기화한다.
54. 개발자로서, 자동 테스트를 명령 하나로 돌리고 싶다. 그래야 변경 후 규칙이 깨지지 않았는지 바로 안다.

## Implementation Decisions

### 구성

- Cargo 워크스페이스 하나에 Dioxus 공식 워크스페이스 템플릿 구조에서 웹만 남긴다: `web`(웹 진입점과 화면), `ui`(공통 화면 컴포넌트), `api`(서버 쪽 전부). 데스크톱과 모바일 패키지는 두지 않는다.
- Dioxus 풀스택(웹 대상)을 쓴다. 구현 시점의 최신 안정 버전을 쓴다.
- 별도 도메인 크레이트는 두지 않는다. 모든 규칙은 `api` 패키지 안의 **onair 서비스**에 모은다.
- 로컬 실행 스크립트(onair와 MediaMTX를 함께 켜기, 테스트 송출)와 MediaMTX 설정은 워크스페이스 안의 도구 폴더에 둔다. 스크립트는 Windows PowerShell 기준이다.

### onair 서비스 (테스트 지점)

모든 규칙은 SQLite 연결과 업로드 폴더 위치를 받아 만드는 onair 서비스 하나가 가진다. 서버 함수, MediaMTX 확인 주소, 채팅 WebSocket은 이 서비스를 그대로 호출하는 얇은 통로다. 서비스가 제공하는 동작:

- **채널 목록**: 모든 채널을 라이브 중인 채널 먼저, 그다음 나머지 순서로 돌려준다. 각 항목에 채널 이름, 프로필 이미지 유무, 라이브 중이면 방송 제목이 들어간다.
- **채널 조회**: 채널 하나와 진행 중인 방송(있다면)을 돌려준다.
- **채널 만들기**: 채널 이름을 받아 채널을 만들고 송출 키를 돌려준다. 이름이 이미 있으면 실패한다. 이름은 앞뒤 공백을 자르고, 비어 있으면 실패한다.
- **스튜디오 들어가기**: 송출 키를 받아 그 채널을 돌려준다. 없는 키면 실패한다.
- **방송 시작**: 송출 키와 제목을 받아 새 방송을 만든다. 진행 중인 방송이 이미 있으면 실패한다. 제목이 비어 있으면 "{채널 이름}의 방송"이 된다.
- **방송 종료**: 송출 키를 받아 진행 중인 방송에 종료 시각을 기록한다. 진행 중인 방송이 없으면 실패한다.
- **영상 수신 허락**: MediaMTX가 넘겨준 송출 키와 동작(송출/재생)을 받아 허락 여부를 돌려준다. 송출은 키가 맞고 그 채널에 진행 중인 방송이 있을 때만 허락한다. 재생은 항상 허락한다.
- **채팅 보내기**: 채널, 닉네임, 내용을 받아 그 채널의 진행 중인 방송에 채팅 메시지를 저장하고, 그 방송을 구독 중인 모두에게 전달한다. 진행 중인 방송이 없거나, 내용이 비었거나, 500자를 넘거나, 닉네임이 비었거나 20자를 넘으면 실패한다.
- **최근 채팅**: 진행 중인 방송의 최근 채팅 메시지 50개를 오래된 순으로 돌려준다.
- **채팅 구독**: 채널의 진행 중인 방송에 새로 올라오는 채팅 메시지를 받는 구독을 돌려준다. 방송이 종료되면 구독 쪽에 종료를 알린다.
- **프로필 이미지 저장**: 송출 키, 파일 내용, 형식을 받아 업로드 폴더에 저장하고 채널에 연결한다. 기존 이미지는 교체한다. jpg/png/webp가 아니거나 2MB를 넘으면 실패한다. 형식은 파일 이름이 아니라 내용으로 판별한다.
- **영상 신호 상태**: 채널에 지금 영상 신호가 있는지 돌려준다. MediaMTX에 물어서 알아낸다.

실패는 사용자에게 그대로 보여 줄 수 있는 이유(예: "이미 있는 채널 이름입니다")를 담는다.

### 데이터

SQLite 파일 하나를 쓴다. 서버 시작 시 스키마를 만들고, 채널이 하나도 없으면 테스트 채널 3개를 넣는다. 테스트 채널의 송출 키는 고정값으로 해서 개발 문서에 적는다.

- **채널**: 아이디, 이름(유일), 송출 키(유일), 프로필 이미지 파일 이름(없을 수 있음), 만든 시각
- **방송**: 아이디, 채널 아이디, 제목, 시작 시각, 종료 시각(진행 중이면 없음). 채널마다 종료 시각이 없는 방송은 최대 하나.
- **채팅 메시지**: 아이디, 방송 아이디, 닉네임, 내용, 보낸 시각

끝난 방송의 채팅 메시지는 지우지 않지만 첫 버전 화면에서는 보여 주지 않는다.

### 송출 키

- 채널을 만들 때 추측하기 어려운 무작위 문자열로 만든다. 송출 키라는 걸 알아보기 쉽게 앞에 고정 접두어를 붙인다.
- 화면에 노출되는 채널 주소에는 송출 키 대신 채널 아이디를 쓴다.
- 시청자 쪽 응답에는 송출 키를 절대 담지 않는다.

### MediaMTX 연동 (ADR-0001)

- OBS는 RTMP로 MediaMTX에 송출하고, 송출 키를 경로 이름으로 쓴다.
- MediaMTX는 외부 HTTP 인증을 켜서, 송출과 재생 요청마다 onair의 확인 주소를 호출한다. onair는 **영상 수신 허락** 결과로 응답한다.
- 시청자에게 송출 키가 노출되지 않도록, 영상은 채널 아이디로 된 공개 경로로 재생한다. 송출 키 경로에서 채널 아이디 경로로 넘기는 방식은 MediaMTX 설정으로 처리한다. MediaMTX 설정만으로 불가능하면 구현 시 대안을 정하고 이 명세에 기록한다.
- 시청자 브라우저는 HLS로 재생한다. HLS 재생은 브라우저 기본 기능이나 hls.js를 쓴다.
- 영상 신호 상태는 MediaMTX의 API로 확인한다.

### 채팅 전송

- 채팅은 Dioxus 서버 함수의 WebSocket으로 주고받는다. 별도 실시간 서버는 두지 않는다.
- 서버는 진행 중인 방송마다 메모리 안의 전달 통로를 두고, 채팅 메시지를 저장한 뒤 그 통로로 구독자 모두에게 보낸다.
- 시청자가 채널 페이지에 들어오면 최근 50개를 받고 구독을 시작한다.

### 브라우저 저장

- 닉네임과 송출 키는 브라우저 로컬 저장소에 둔다.
- 스튜디오에서 나가기를 누르면 저장된 송출 키를 지운다.

### 화면

- 첫 화면: 채널 목록
- 채널 페이지: 플레이어, 채널 정보, 방송 제목, 채팅
- 스튜디오: 송출 키가 없으면 "채널 만들기"와 "송출 키로 들어가기", 있으면 채널 관리(서버 주소와 송출 키, 영상 신호 상태, 방송 시작/종료, 프로필 이미지)

## Testing Decisions

- 좋은 테스트는 사용자가 하는 행동 순서대로 onair 서비스를 호출하고 결과만 확인한다. 테이블 구조, SQL, 내부 함수 같은 구현 세부는 확인하지 않는다. 구현을 바꿔도 동작이 같으면 테스트는 그대로 통과해야 한다.
- 테스트 지점은 **onair 서비스 한 곳**이다. 테스트마다 비어 있는 임시 SQLite와 임시 업로드 폴더로 서비스를 만든다.
- 채팅 실시간 전달은 같은 방송을 구독한 둘 중 하나가 보내면 다른 쪽이 받는지로 확인한다. 실제 WebSocket 연결은 테스트하지 않는다.
- 영상 신호 상태처럼 MediaMTX에 묻는 부분은 MediaMTX 없이도 테스트할 수 있도록, 서비스가 MediaMTX에 묻는 부분을 바꿔 끼울 수 있게 만든다.
- 확인할 규칙 예: 같은 이름의 채널 거부, 틀린 송출 키로 스튜디오 거부, 진행 중일 때 방송 시작 거부, 방송 시작 전 송출 거부, 방송 종료 후 송출 거부, 방송 없을 때 채팅 거부, 새 방송의 채팅은 비어 있음, 최근 채팅은 50개까지 오래된 순, 빈 제목은 "{채널 이름}의 방송", 채널 목록은 라이브 중 먼저, 프로필 이미지 형식·크기 거부, 시청자 응답에 송출 키 없음.
- 화면과 실제 영상 재생은 자동 테스트하지 않는다. 로컬 실행 스크립트와 테스트 송출 스크립트로 직접 확인한다.
- 기존 테스트가 없는 새 저장소라 따를 선례는 없다. 이 명세의 테스트가 이후의 선례가 된다.

## Out of Scope

- 로그인, 회원가입, 권한(송출 키가 임시로 그 역할을 한다)
- 시청자 수, 팔로우, 카테고리, 검색
- 다시보기(VOD), 클립, 끝난 방송의 채팅 보기
- 후원(치즈), 구독, 이모티콘
- 브라우저 직접 송출(WebRTC/WHIP)
- 방송 중 제목 변경
- 송출 키 재발급, 채널 이름 변경, 채널 삭제
- 채팅 관리(금지어, 강퇴, 슬로우 모드)
- 데스크톱·모바일 앱
- 배포(첫 버전은 로컬에서만 실행)
- 화면과 영상 재생의 브라우저 자동 테스트(E2E)
